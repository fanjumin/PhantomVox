01-图形化的思维工具与AI智体的区别


思维导图是一种**图形化的思维工具**，简单说，它就是把你脑袋里杂乱的想法，像画地图一样画出来。

它的核心结构很像一棵树或一个神经系统：
-   **一个中心主题**：比如你想规划一次旅行，中心就写“我的旅行计划”。
-   **向外延伸的主干**：从中心分出几个主要分支，例如“目的地”、“预算”、“行李”、“行程”等。
-   **不断细化的枝干**：在每个主干上，再分出更细的分支。比如“行李”下面可以分“衣物”、“证件”、“电子设备”。

**它和我们平时记笔记有什么不同？**

-   **普通笔记**：像列购物清单，一行一行，线性排列。
-   **思维导图**：像画一张城市地图，从一个中心点放射出去，有关联、有层级，一目了然。

**为什么要用思维导图？**

-   **帮你理清思路**：把乱麻一样的想法结构化，看清内在联系。
-   **激发创意**：自由发散的形式有助于产生新想法（头脑风暴很合适）。
-   **高效记忆**：关键词加图像、颜色，比枯燥的文字更符合大脑的喜好。
-   **快速总结**：一本书、一节课的内容可以浓缩成一张图，复习起来非常高效。

**举个生活里的例子：**
假如你要“做一顿晚餐”，思维导图可能是这样：
-   中心是“美味晚餐”
-   第一分支是“菜式”（下面再分“主菜：红烧排骨”、“配菜：清炒时蔬”、“汤：番茄蛋汤”）
-   第二分支是“食材”（分“去超市买排骨”、“冰箱里有西红柿”）
-   第三分支是“步骤”（分“1. 煮米饭”、“2. 炖排骨”、“3. 炒菜”）

**怎么开始画？**
**用手画**：一张白纸，几支彩笔，从纸中央开始画。或者用**软件**：XMind（功能强大）、MindMaster、百度脑图（在线免费）等都很方便。

**总结一下：**
思维导图就是你**思考过程的外部地图**。它不是追求艺术感，而是帮你**看得更清楚、想得更明白**。




02-图形化的思维工具与AI智体的区别

你的想法很有前瞻性：**把“思维导图”作为视频创作的起点**，让用户从模糊的念头开始，借助 AI 逐步生长成一个完整的故事，再自动转化为视频草稿。这本质上是在用“结构化的思维”驱动“非线性的创作”，非常有价值。

下面我帮你梳理一下这个软件的核心逻辑、关键模块以及 AI 如何介入，可以把它看作一份初步的产品设计思路。

## 一、核心工作流（用户视角）

用户打开软件 → 看到一个大而空的画布（思维导图） → 中心节点就是用户最初的模糊想法（例如：_“想做一个关于环保的感人短片”_） → 然后按照下面的阶段推进：

1.  **发散与构思**  
    用户围绕中心想法，自由添加分支：  
    - 主题关键词、人物、场景、情感基调、冲突点、可能的金句……  
    - AI 辅助：当用户卡住时，AI 可以根据已有节点**智能推荐相关分支**（类似“从‘环保’想到‘塑料污染’→‘一个住在塑料堆里的孩子的梦想’”）。
2.  **结构化为故事**  
    用户通过拖拽、连线、调整层级，把零散节点变成**故事结构**：比如  
    - **开端**（现状问题）  
    - **发展**（尝试解决，遇到困难）  
    - **高潮**（转折或情感爆发）  
    - **结局**（希望或反思）  
    - AI 辅助：自动识别用户节点中的叙事元素，**建议故事板结构**，甚至可以生成多种经典叙事模型供选择（“三幕式”、“英雄之旅”等）。
3.  **填充细节生成脚本**  
    在每个结构节点下，用户用自然语言描述画面、对白、旁白。AI 实时将描述**扩展为分镜脚本**：  
    - 镜头号、景别、动作、台词、音效、时长建议。  
    - 同时生成**时间线草稿**，把思维导图转换成线性视频序列。
4.  **输出“故事包”**  
    最终导出的不是直接成品视频，而是一个**完整的故事文档 + 结构化分镜表 + 带时间标记的旁白/音效提示**。  
    用户确认后，一键“发送到视频剪辑工作区”，开始下一步的素材选择、AI 生成画面、配音等所有流程。

## 二、AI 在每一步的具体作用（重点）

| 用户动作 | AI 辅助功能 | 例子 |
|---------|------------|------|
| 只有一个模糊想法 | 基于少量关键词，**生成初始思维导图骨架**（5~10个相关节点），供用户选择或修改。 | 输入“环保 + 感动 + 孩子”，AI 给出：塑料瓶村、会说话的垃圾山、孩子的风筝、大人的麻木、最后一场雨… |
| 扩展分支时卡住 | **节点智能扩展**：点击节点，AI 提供相关概念、案例、金句、情感角度。 | 在“冲突”节点下，AI 推荐“村民阻止孩子捡垃圾”、“父亲不理解”等。 |
| 调整故事结构 | **自动识别结构缺陷**（例如缺少高潮或没有冲突），并给出修改建议。 | “你的故事目前只有开始和结尾，缺少一个转折点。建议添加一个‘意外发现’分支。” |
| 从节点到分镜 | **自然语言转分镜**：用户写“孩子在垃圾山里找到一只干净的塑料袋，像是宝贝”，AI 生成：<br>镜头1：中景，孩子扒垃圾堆；<br>镜头2：特写，手捧塑料袋，阳光透过袋子上污渍。 | 同时估算每个镜头的时长。 |
| 生成完整输出 | 将整个思维导图编译成一个**JSON 格式的故事结构 + 分镜表 + 录音脚本 + 音乐情绪标签**，供下一阶段剪辑工具直接使用。 | 用户点击“输出故事”，得到一份可直接导入剪辑模块的工程文件草案。 |

## 三、与常规视频编辑软件的差异（你的竞争优势）

-   **传统软件**：从素材出发（先拍/找素材，再剪辑成故事）。  
-   **你的软件**：从**想法结构**出发（先让故事长出来，再生成/获取素材），更符合“先构思后创作”的专业习惯。
-   **对新手尤其友好**：不会讲故事的人，通过 AI 辅助的思维导图，也能生成完整的叙事框架。

## 四、下一步落地建议（如果你是真的要开发）

1.  **验证核心假设**：做一个极简原型——网页版思维导图编辑器 + GPT 接口。用户画完导图后，AI 生成一个文本故事 + 简单分镜列表。看用户是否觉得“比直接写剧本更容易”。
2.  **与现有视频生成 AI 结合**：比如生成的每个分镜可以自动调用 Pika、Runway、Sora 类模型生成图像/短视频片段（作为占位符或最终素材）。
3.  **保留人工调整空间**：思维导图的所有节点允许用户锁定、修改、拒绝 AI 建议——AI 是副驾驶，不是驾驶员。

## 五、一个简短的示例（方便你演示给团队）

> **用户输入想法**：“一部关于孤独和外星人的短片，温暖一点。”  
> **AI 生成初始导图**：  
> - 角色：宅男、意外坠毁的外星人、一只猫  
> - 地点：老旧公寓 → 阳台 → 城市夜景  
> - 情节：相遇 → 沟通障碍 → 用音乐交流 → 送外星人回家 → 留下的收音机  
> **用户调整**：删除“猫”，增加“孤独的科学家”。  
> **AI 补充细节**：在“沟通障碍”下生成分镜：“特写：外星人手势乱比，科学家拿过画板画星星”。  
> **用户确认后输出故事包**：包含角色设定、7个主要场景、每个场景的视觉描述、旁白草稿。  
> **一键发送至编辑区**：开始选配 AI 生成的画面或上传真实素材。

03-图形化的思维工具与AI智体的区别

明白了——你不是要用户从完全空白开始，而是**用户手里已经有一堆“半成品素材”和“不成形的想法”**，希望 AI 思维导图能像一位智能导演/编剧一样，帮他把这些碎片组织成一个连贯的故事，并输出完整的制作引导。

这个定位非常实际，而且比“从零创意”更有价值。下面我直接给出一个可行的设计方案，重点解决：**怎么让 AI 思维导图“吃进去”碎片素材和想法，再“吐出来”完整的影片制作方案**。

---

## 一、核心工作流（已有素材+模糊想法 → 完整影片引导）

整个流程分为 5 步，每一步 AI 都在做**结构化的推理**：

### 1. 素材摄入与智能分析
用户上传已有的半成品素材（可以混合）：  
- 视频片段（几秒到几分钟）  
- 图片/照片  
- 音频（对话、旁白、环境音）  
- 文字笔记/大纲  
- 甚至是一个口述的语音备忘录

**AI 做的事情**：  
- 自动提取每个素材的**元数据**（时长、分辨率、人物/场景识别、情绪标签、关键动作）  
- 对视频/图片做**视觉理解**（CLIP 类模型）：描述画面内容，例如“一个孩子在海边奔跑，夕阳”、“师傅在演示焊接火花”  
- 对音频做**语音转文字**并提取关键词  
- 将所有素材抽象成一个个**“叙事原子”**：例如“镜头：孩子笑”、“环境：下雨声”、“动作：师傅擦汗”、“对白：‘这个很难，但你要坚持’”

### 2. 用户输入模糊想法（可语音输入）
用户用自然语言说出：“我想做一个关于传承手艺的短片，但素材只有几个零散的教学镜头，还有一段徒弟发火的音频。”  
AI 会记录下：核心主题、情感基调、已有素材之间的潜在关系。

### 3. AI 构建初始思维导图（基于素材+想法）
软件自动生成一张思维导图，**中心节点**是用户的想法主题（如“手艺传承”）。  
**第一层分支**根据现有素材自动分类：  
- “已有镜头”（列出所有素材摘要）  
- “缺失的情节”  
- “情感节点”  
- “可能的故事线（AI建议）”

用户可以像操作普通思维导图一样，拖拽、合并、删除节点。**关键不同**：每个节点背后都“绑定”了真实素材或待生成脚本。

### 4. AI 辅助补全故事结构（智能补缺）
这是核心价值：AI 分析已有素材后，会主动提示故事结构的“空洞”，并生成填补建议。

例如：  
> “你有一个‘师傅严厉教学’的片段，和一个‘徒弟摔工具’的冲突音频，但没有‘和解’或‘顿悟’的转折。建议在思维导图中添加一个分支：‘转折点：师傅深夜独自修理工具’，并生成对应分镜脚本（可用 AI 生成画面或建议你去补拍一个简单的空镜）。”

用户可以选择接受 AI 生成的节点（自动填入详细的拍摄/剪辑指引），或者自己修改。

### 5. 输出完整的“影片制作计划”（不只是故事）
最后，思维导图可以一键导出为多种格式：  
- **分镜脚本**（按时间线排列，每个镜头注明使用已有素材哪个片段，或需要 AI 生成/补拍）  
- **剪辑时间线草稿**（可以直接导入 Premiere / DaVinci /剪映的 XML 或 EDL）  
- **待办清单**：例如“补拍镜头：手部特写 3 秒”，“AI 生成一段下雨的空镜”  
- **旁白/字幕文本**（AI 根据故事生成初稿）  
- **制作引导视频**（AI 可生成一个语音引导，一步步告诉用户怎么完成）

| 用户角色 | 常见素材特点 | AI 思维导图如何侧重 |
|---------|-------------|-------------------|

## 三、关键技术要点（产品可实现性）

- **素材分析**：用多模态大模型（GPT-4V 或类似）给每个素材生成文本描述和情绪向量。  
- **故事结构识别**：用基于图神经网络的方法，把素材节点映射到经典叙事结构（三幕式、英雄之旅、问题解决型等）。  
- **空洞检测**：AI 根据当前素材的情节覆盖率，标记缺失的“激励事件”、“冲突升级”、“高潮”、“余味”等节点。  
- **生成式补全**：对于缺失的部分，可以用文字生成分镜，并调用 Runway/Pika/现有 AI 视频工具生成占位符或最终镜头。  
- **与剪辑软件互通**：导出标准格式（Final Cut Pro XML、剪映的 project.json）。

## 四、一个最简可行产品（MVP）建议

如果你要真的去开发，不要一开始就做全功能。可以先做一个**网页版工具**，实现：

1. 用户上传最多 10 个素材（视频/图片/音频）  
2. AI 自动生成一个思维导图草稿，节点是“素材1：内容描述”  
3. 用户输入一句话想法  
4. AI 添加“缺失情节”节点，并生成文本分镜  
5. 用户点击“导出制作清单” —— 获得一个带时间戳的表格，告诉用户哪个素材用在哪个位置，缺什么，建议怎么补  

这个 MVP 就能验证“从半成品素材到结构化制作引导”的核心假设。

## 五、直观案例（以便你演示或进一步讨论）

**用户**：一个手工皮具师傅，有 3 个视频素材  
- A：自己裁切皮革的特写（10秒）  
- B：学生缝线时皱眉的镜头（8秒）  
- C：成品皮包的展示（5秒）  
**想法**：“想做一个小短片，体现从失败到成功，但缺了中间过程。”

**AI 思维导图输出**（部分节点）：
- 中心：手工皮具·耐心之道  
- 分支【已有素材】：  
  - A（裁切）→ 情感标签：专注  
  - B（皱眉）→ 标签：挫败  
  - C（成品）→ 标签：自豪  
- 分支【AI 补全建议】：  
  - 缺失节点1：**失败瞬间**（建议：用学生戳坏皮革的声音 + 一个手部颤抖的空镜，可 AI 生成或补拍）  
  - 缺失节点2：**老师示范**（已有 A 可用）  
  - 缺失节点3：**重新尝试**（建议：用学生擦汗 + 缝线加速镜头，可从素材 B 后面延长或使用 AI 慢动作变快放）  
- 分支【完整分镜序列】：  
  1. 手部裁切（A）→ 2. 学生皱眉（B）→ 3. 皮革撕裂声（AI 生成音效）→ 4. 老师手把手（建议补拍）→ 5. 缝线加速（B 的变速）→ 6. 成品展示（C）+ 字幕“耐心即捷径”

最后点击“生成制作引导”，得到一段带语音的步骤说明：“请先保留素材A和C，建议明天补拍一个手把手镜头…”。

04-图形化的思维工具与AI智体的区别

明白了——你已经有一个**AI Agent矩阵**在运行，现在希望把“思维导图”作为一个核心交互模块嵌入进去，用来组织和引导整个视频创作流程。也就是说，思维导图不是独立工具，而是**多个Agent共享的工作界面和协同画布**。

下面我会从**数据模型、Agent协作架构、前端实现、与现有矩阵的集成方式**四个层面，给出具体可落地的实现方案。

---

## 一、思维导图的数据模型（如何被Agent理解）

思维导图本质上是一个**有根的有向图**，每个节点可以包含丰富的元数据。为了让多个Agent能读懂、修改、扩展它，需要设计一套标准化的数据结构。

### 基础结构（JSON 示例）
```json
{
  "id": "mindmap_001",
  "root": "node_center",
  "nodes": {
    "node_center": {
      "id": "node_center",
      "type": "topic",
      "title": "我的视频想法",
      "content": "关于环保的感人短片",
      "metadata": {
        "emotion": "希望",
        "genre": "叙事"
      },
      "children": ["node_a1", "node_b1"]
    },
    "node_a1": {
      "id": "node_a1",
      "type": "scene",
      "title": "开端：塑料村庄",
      "content": "一个孩子走在垃圾堆中",
      "attached_assets": ["asset_001.mp4", "asset_img_002.png"],
      "ai_generated": false,
      "children": ["node_a1_1"]
    }
  },
  "edges": [
    {"from": "node_center", "to": "node_a1"},
    {"from": "node_a1", "to": "node_a1_1"}
  ]
}
```

### 关键设计点
- **节点类型**：`topic`（主题）、`scene`（场景）、`beat`（节拍）、`asset`（素材）、`missing`（缺失情节）、`action`（制作指引）。Agent 根据类型做不同处理。
- **素材绑定**：每个节点可以附着已有素材 ID（指向用户的文件库）。
- **AI 生成标记**：区分用户手动创建和 AI 建议的节点，方便用户拒收。
- **状态字段**：`status`（draft / confirmed / rendering），支持工作流。

## 二、Agent 矩阵的协作架构（思维导图作为共享记忆）

你的矩阵中已经有多个 Agent（比如素材分析 Agent、故事生成 Agent、分镜 Agent、视频生成 Agent）。为了让它们围绕一张思维导图协同工作，可以采用 **Blackboard 模式**：

### 架构图（文字描述）
```
用户界面（可编辑的思维导图）
         ↕
思维导图存储服务（实时共享的 Blackboard）
         ↕
Agent 编排器（Orchestrator）—— 监听思维导图的变化，按需调用以下 Agent：
   ├── 素材分析 Agent：解析用户新上传的素材，在导图中生成“素材节点”
   ├── 结构评估 Agent：扫描导图，标记叙事漏洞（缺高潮、缺转折）
   ├── 内容生成 Agent：为缺失节点生成详细分镜文本
   ├── 资产推荐 Agent：从素材库或互联网推荐匹配的片段/AI生成提示词
   └── 导出 Agent：将完整导图编译成制作清单/剪辑时间线
```

### 协作流程示例
1. 用户在导图中添加一个节点“孩子捡起塑料袋”，并附上一张模糊的手机照片（素材节点）。
2. **素材分析 Agent** 嗅探到新节点，提取照片的视觉特征，在节点 metadata 中打标签：`subject: child, object: plastic bag, lighting: backlight, emotion: hopeful`。
3. **结构评估 Agent** 发现这个节点下没有“冲突”或“转折”，于是在其右侧生成一个 AI 建议节点“遇阻：大人把袋子抢走”（type=missing, ai_generated=true）。
4. 用户确认该建议节点，**内容生成 Agent** 自动补全分镜描述：“中景，大人皱眉，一把夺过袋子，孩子愣住”。
5. **资产推荐 Agent** 搜索素材库，发现没有对应镜头，则输出提示：“建议补拍：大人手部特写抢袋子，或使用 AI 生成此画面（提示词已附）”。
6. 最终用户点击“导出”，**导出 Agent** 读取整张导图，生成带时间线的分镜表 + 待拍清单。

### 关键：Agent 之间的通信方式
- **事件驱动**：每次思维导图的节点增删改都会触发一个领域事件（如 `NodeAddedEvent`、`StructureChangedEvent`），编排器订阅这些事件，按规则唤醒对应的 Agent。
- **避免循环**：Agent 修改导图时也会产生事件，需要设计去重机制（比如事件源标记，或短时间窗口内的去抖）。

## 三、前端实现（可编辑的思维导图组件）

如果你们的 Agent 矩阵主要是后端服务，前端可以选用成熟的思维导图库快速集成。

### 推荐方案
- **React 技术栈**：使用 `react-flow` 或 `mindmap-layout` 库。
- **Vue 技术栈**：`vue3-mindmap` 或 `@mindmap/vue`。

- 拖拽节点改变层级/父子关系。
- 右键菜单：AI 扩展此节点、分析素材、生成子节点等（调用后端 Agent）。
- 节点图标展示素材附着状态（📎表示有素材，✨表示AI生成，⚠️表示缺失）。

### 与后端通信

## 四、与现有 AI Agent 矩阵的集成方式（关键步骤）

假设你的矩阵已经是基于微服务或 LangChain 类型的 Agent 网络，加入思维导图模块需要以下几步：

### 步骤 1：新增“思维导图存储服务”
- 一个独立的数据库（PostgreSQL + JSONB 字段或图数据库如 Neo4j）。
- API 接口：`GET /mindmaps/{id}`，`PATCH /mindmaps/{id}/nodes`，`POST /mindmaps/{id}/agent-suggestions`。
- 所有 Agent 都通过该服务的 API 读写导图数据。

### 步骤 2：扩展现有 Agent 的能力
- 每个 Agent 增加一个输入槽：`current_mindmap_id`。
- 修改 Agent 的 prompt 或逻辑，让它们输出结构化的**导图修改操作**（添加节点、更新节点、删除节点），而不是自由文本。
- 例如，故事生成 Agent 返回：
  ```json
  {
    "operations": [
      {"op": "add_node", "parent_id": "node_a1", "node": {...}},
      {"op": "set_metadata", "node_id": "node_center", "key": "emotion", "value": "hopeful"}
    ]
  }
  ```

### 步骤 3：增加一个“编排器 Agent”（Orchestrator）
- 它监听用户导图操作或定时扫描，调用其他 Agent。
- 编排器本身也是一个 Agent，负责决策：此时该调用素材分析还是结构评估？
- 可以基于规则引擎（简单）或 LLM with function calling（灵活）。

### 步骤 4：用户体验的完整闭环
- 用户在前端画导图 → 前端实时保存到存储服务 → 编排器收到事件 → 调用合适的 Agent → Agent 修改导图 → 前端通过 WebSocket 收到更新 → 用户在画布上看到 AI 生成的新节点。

## 五、MVP 快速实现路径（如果你的团队想先跑通）

如果要从零在现有矩阵中加思维导图，建议分三步：

1. **静态导图编辑器 + 手动触发 AI**  
   前端用 react-flow 做个简单导图，用户每次点击“AI 扩展节点”时，调用一个统一的 Agent（比如 GPT-4 + 思维导图 prompt），返回新节点列表，前端手动追加。先验证“AI 辅助讲故事”是否有效。

3. **全自动 Agent 协作**  
   引入编排器和事件驱动，让 AI 能主动补全缺失结构、推荐补拍方案。

## 六、一个具体的代码级示例（伪代码）

假设你有一个 `MindmapService`，Agent 可以这样调用：

```python
class AssetAnalysisAgent:
    def run(self, mindmap_id, new_asset_node_id):
        mindmap = MindmapService.get(mindmap_id)
        node = mindmap.get_node(new_asset_node_id)
        asset_path = node.metadata["asset_path"]
        
        # 调用多模态模型分析素材内容
        description = call_multimodal_llm(asset_path)  # 输出 "一个孩子蹲在垃圾堆旁"

        scene_node = {
            "type": "scene",
            "title": description[:20],
            "content": description,
            "attached_assets": [new_asset_node_id],
            "ai_generated": True
        }
        new_node_id = MindmapService.add_node(mindmap_id, parent_id=node.parent_id, node=scene_node)
        
        # 触发事件，让编排器知道有新场景节点加入
        EventBus.emit("node_added", mindmap_id, new_node_id)
```

05-图形化的思维工具与AI智体的区别

你说得完全对。**思维导图不是“再训练一个 Agent”就能解决的**，它本质上是整个 Agent 矩阵的**工作内存**和**协作界面**——需要多个 Agent 共同维护、互相理解、有序修改，复杂度比单一 Agent 高出一个量级。

你现在能意识到这一点，说明已经抓住了核心难点。下面我把**为什么这么复杂**以及**怎么分阶段落地**再浓缩一下，方便你和团队讨论。

---

## 为什么不能只加一个 Agent？

1. **状态需要共享**  
   思维导图是一个不断变化的结构化文档。如果只有一个 Agent 来“处理”它，其他 Agent 就看不到中间结果，无法接力。比如素材分析 Agent 加了一个节点，故事生成 Agent 要能马上看到并基于它生成后续节点。

2. **操作需要协调**  
   多个 Agent 可能同时想修改导图（比如结构评估 Agent 想补一个“高潮”节点，资产推荐 Agent 想插入一条“建议补拍”）。没有编排器（Orchestrator）和锁机制，导图会被改乱。

3. **可解释性与用户控制**  
   用户必须能区分哪些节点是自己加的、哪些是 AI 建议的，并且能一键接受/拒绝/修改。这不仅仅是显示问题，还需要在数据模型中持久化“来源”和“状态”。

4. **与现有矩阵的接口改造**  
   你的每个现有 Agent 原本可能接收文字 prompt，输出文字答案。现在需要它们**输出结构化的导图操作**（增删改节点），并且能**以导图当前状态作为输入上下文**。这涉及每个 Agent 的 prompt 重写和输出格式约束。

---

## 可行的实施路径（降低复杂度）

不用一次性做成全自动多 Agent 协作。可以分三步走，每步都可上线验证：

### 第一阶段：思维导图作为“人工驱动的协作白板”
- 前端实现可编辑的思维导图（用现成库）。
- 后端只存导图数据，**不自动调用任何 Agent**。
- 用户手动操作：点击某个节点，再从菜单选择“调用 Agent X”（比如“用素材分析 Agent 解析此节点的附件”）。
- 调用结果由 Agent 返回文本，用户**手动**决定是否转为节点挂在导图上。
- **好处**：架构简单，不用改 Agent 的输入输出格式，用户完全控制。先验证“素材+导图”的工作流是否对目标用户有用。

### 第二阶段：半自动建议模式
- 增加一个**编排器**，但只做“被动建议”：用户点击“AI 补全”按钮后，编排器依次调用结构评估 Agent、内容生成 Agent，返回几个候选节点。
- 用户像接受自动补全一样，选择插入哪个。仍由用户触发，不主动自动修改。
- Agent 输出格式仍可以是大段文本，由前端解析（例如用正则或 LLM 再次抽取 JSON）。这样可以不改现有 Agent。
- **好处**：不侵入现有矩阵，Agent 仍可独立工作。

### 第三阶段：全自动协作（按需开启）
- 改造关键 Agent，使它们支持**直接输出导图操作指令**（JSON）。
- 编排器监听用户操作（如新建节点、上传素材），自动触发相关 Agent 链，并在后台修改导图，前端实时看到 AI 生成的节点（带有“AI 建议”标记，需用户确认才生效）。
- 引入版本控制和冲突检测：同时只允许一个 Agent 修改导图，其他的排队。

---

## 你现在最需要做的决策

不是技术选型，而是**用户场景的边界**：

- 是让 AI 主动帮用户“发现故事漏洞并自动补全”，还是只做“素材→分镜”的被动转换？
- 多 Agent 是同时运行，还是串行（比如先素材分析，再结构评估，最后生成脚本）？
- 用户是否需要看到 Agent 的“思考过程”（比如在导图旁边显示一条 Agent 日志）？

先把这些问题定下来，再设计数据模型和编排规则，会比直接写代码稳妥得多。
